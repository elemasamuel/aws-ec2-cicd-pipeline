# DevOps notes — 2026-11-20

## Where the pipeline stands
- Jenkins (shared library) on `origin/main`: bump version -> npm tests -> build/push image -> deploy to EC2 via scp + `docker-compose up -d` -> commit version bump.
- GitHub Actions `ci.yml`: tests on push/PR, then Docker image build check.
- Compose service has `restart: unless-stopped` and a `/health` healthcheck (wget, 30s interval).
- Makefile: install, test, run, docker-build, docker-run.

## Observations / improvement ideas
- Jenkinsfile hardcodes the EC2 IP and uses `StrictHostKeyChecking=no` — pin the host key or use a Jenkins credential/parameter.
- Dockerfile copies only `package.json`, so `npm install` is not reproducible; copy `package-lock.json` and use `npm ci`.
- `node:18-alpine` is EOL; move to a current LTS and run as a non-root user.
- Compose image tag depends on `IMAGE_TAG` being set; add a default or fail fast.
- Deploy has no post-deploy verification; add a curl to `/health` after `up -d`.
- Compose `version:` key is obsolete in Compose v2.

## Concepts to review
- Healthchecks vs restart policies (restart does not act on "unhealthy").
- Layer caching order in Dockerfiles.
- Immutable, versioned image tags vs `latest` for rollbacks.
