# DevOps notes — 2026-11-19

## Pipeline snapshot (this repo)
- **Jenkins** (`Jenkinsfile`): bump version -> test -> build/push image -> deploy to EC2 -> commit version. Everything except tests runs only on `origin/main`; deploy is also gated by the `deploy` boolean param.
- **GitHub Actions** (`.github/workflows/ci.yml`): `test` (Node 18, `npm ci`, `npm test`) then `docker-build` (build only, no push) on PRs and pushes to `main`.
- **Deploy**: `scp` docker-compose.yaml to EC2, then `IMAGE_TAG=<ver> docker-compose up -d` over ssh. Compose has a `/health` healthcheck and `restart: unless-stopped`.
- **Image**: `node:18-alpine`, package.json copied before source so the `npm install` layer is cached.

## Things worth revisiting
- Jenkinsfile deploys with `StrictHostKeyChecking=no` — pin the EC2 host key instead.
- EC2 IP is hardcoded in the Jenkinsfile; move to a parameter/credential or DNS name.
- Dockerfile uses `npm install`; `npm ci` with the lockfile gives reproducible builds (and copy `package-lock.json`).
- Container runs as root; add `USER node`.
- Node 18 is end-of-life; consider bumping the base image and CI `node-version` together.
- Compose `version:` key is obsolete in Compose v2.
- Two CI systems (Jenkins + Actions) overlap on tests; decide which is the source of truth.

## Concepts to remember
- Immutable image tags (version per build) make rollbacks a re-run of `docker-compose up` with an older `IMAGE_TAG`.
- Healthchecks only report state; `restart` policies don't act on `unhealthy` — use an orchestrator or autoheal for that.
